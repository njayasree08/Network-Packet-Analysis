A complete academic full-stack web application combining a visual network topology
simulator (inspired by Cisco Packet Tracer) with a machine learning intrusion
detection pipeline.

This project lets you design a network topology, generate synthetic traffic, and use
an ML-based intrusion detection model to classify traffic as BENIGN, DoS, PortScan,
BruteForce, or other network attack classes. It includes a FastAPI backend, a React
frontend, SQLite storage, and model evaluation dashboards.

---

## Features

- Visual network topology builder with draggable devices and connection creation
- Device configuration editor for IP, subnet mask, gateway, and metadata
- Traffic generator for normal and malicious attack scenarios
- ML inference pipeline with feature mapping and preprocessing
- Dashboard cards and charts for traffic analytics and model metrics
- Confusion matrix, feature importance, and benchmark analysis view
- Prediction history with classification results and confidence levels

## Project Notes

- The backend is built with FastAPI and serves the application API and dashboard data.
- The frontend is built with React + Vite and displays the simulator, dashboard, and ML analytics screens.
- Data is stored in SQLite using SQLAlchemy models under the backend app.
- The ML training scripts live in the top-level `ml/` folder and generate synthetic intrusion-detection data.
- Model artifacts are stored in `backend/models/` and are used by the prediction pipeline at runtime.
- The app is intended for academic or demo purposes and uses synthetic traffic patterns rather than live network telemetry.

## Using the Application

### Network Simulator (main page)

1. Navigate to **Network Simulator** in the sidebar.
2. Click a device type in the palette (PC, Server, Router, Switch, Firewall, Laptop) to add it to the canvas.
3. **Connect devices** by dragging from one node handle to another, or click "Connect" mode to click source → destination.
4. Click any device to open its **Configuration panel** (set IP, subnet mask, gateway, etc.).
5. Click **Traffic & Predict** to open the Traffic Generator panel.
6. Select source device, destination device, protocol, ports, packet count, and **traffic scenario**.
7. Click **Generate Traffic & Predict** — the app generates flow features and runs the ML model.
8. The **Prediction Panel** shows the result, confidence, class probabilities, and highlights the affected path on the canvas.

### Dashboard

- View summary cards: total devices, connections, flows, predictions.
- Charts: Normal vs Malicious, Attack Distribution, Protocol Distribution, Attacks by Device.
- Recent predictions table.

### Prediction History

- Full table of all ML predictions with expandable rows for probabilities.
- Filter by: All, Malicious, BENIGN, DoS, PortScan, BruteForce.

## Adapting to Your Own Trained Model

### 1. Replace the model file

Place your trained model at:
```
backend/models/ids_model.joblib    (or ids_model.pkl)
backend/models/scaler.pkl          (if you used a scaler)
backend/models/label_encoder.pkl   (if you used a LabelEncoder)
```

### 2. Update feature column names

Edit `backend/app/ml/feature_mapper.py`:
- Set `MODEL_FEATURE_COLUMNS` to the exact list of feature names your model was trained on (same order).
- Add entries to `FEATURE_ALIASES` if your dataset used different column names.
- Set `DEFAULT_VALUES` for any features your model expects but the simulator doesn't generate.

### 3. Update label mapping

Edit `backend/app/ml/predict.py`:
- Update `LABEL_DISPLAY_MAP` to map your model's raw label strings to display names.

### 4. No scaler / encoder?

If your model was not trained with a scaler or label encoder, simply leave
`backend/models/scaler.pkl` and `backend/models/label_encoder.pkl` absent —
the system detects missing files and skips those steps automatically.

## ML Pipeline

```
User creates topology
        ↓
User selects traffic scenario (normal / dos / port_scan / bruteforce)
        ↓
POST /api/traffic/generate
  → network/traffic.py generates 69 CICIDS-compatible flow features
        ↓
POST /api/predict
  → ml/feature_mapper.py  maps features to MODEL_FEATURE_COLUMNS
  → ml/preprocess.py      applies scaler (if present)
  → ml/model_loader.py    loads ids_model.joblib
  → ml/predict.py         calls model.predict() + predict_proba()
        ↓
Prediction + confidence returned
        ↓
Frontend highlights affected devices/connections on topology canvas
        ↓
Dashboard updated with new prediction record
```

## Traffic Scenarios

| Scenario | Label | Pattern |
|----------|-------|---------|
| normal | BENIGN | Standard bidirectional flow |
| dos | DoS | High forward packet rate, minimal backward traffic, SYN+RST flags |
| port_scan | PortScan | Very short flows, 1–3 packets, SYN+RST, varying destination ports |
| bruteforce | BruteForce | Repeated flows to auth ports (22, 21, 3389) |

> These are synthetic academic simulations. No real network traffic is generated.
